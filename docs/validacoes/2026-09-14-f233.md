# F233 — skills condicionadas à prontidão da captura

## Objetivo

Evitar que uma LLM trate um inventário antigo, ausente ou sem captura válida
como estado atual ao responder perguntas de build e farm.

## Implementação

- contrato comum passa a consultar `get_capture_inbox_status` quando a pergunta
  depende de inventário;
- `warframe-builds` e `warframe-farm` exigem `state=ready`, heartbeat fresco e
  marcador válido para afirmar posse atual;
- versões das skills foram incrementadas para 4;
- demais respostas continuam podendo usar catálogo/World State, mas devem
  declarar a ausência de inventário pessoal.

## Validação

- frontmatter e referências revisados manualmente;
- `git diff --check` sem erros;
- o validador automático não executou porque o ambiente não possui o módulo
  Python `yaml` (`ModuleNotFoundError`), sem alteração dos arquivos de skill.
