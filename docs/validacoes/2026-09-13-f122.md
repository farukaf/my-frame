# Validação F122 — atualização com MCP ativo

O cenário antigo do upgrade validava apenas raízes separadas. F122 adiciona um
gate sobre a mesma raiz: a versão antiga inicializa `data.db`, depois a antiga e
a nova ficam abertas simultaneamente, encerram por EOF e o banco é verificado ao
final.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-McpActiveUpgrade.ps1 `
  -OldDistributionPath .\artifacts\MyFrame-0.0.6-win-x64 `
  -NewDistributionPath .\artifacts\MyFrame-0.0.7-win-x64
```

Resultado observado em 13/09/2026:

```text
MCP_ACTIVE_UPGRADE_OK=1
MCP_ACTIVE_UPGRADE_MODE=old-and-new-same-root
MCP_ACTIVE_UPGRADE_SEED_STRUCTURED=1
MCP_ACTIVE_UPGRADE_BOTH_EXITED=1
MCP_ACTIVE_UPGRADE_SQLITE_PRESERVED=1
```

Por compatibilidade histórica, a raiz é semeada pelo MCP Debug atual e depois
aberta pelas duas distribuições versionadas; assim a evidência testa coexistência
e preservação, sem atribuir suporte SQLite retroativo à distribuição antiga.

Esse gate cobre coexistência/reabertura segura. Ele não substitui instalador
Windows, registro de cliente MCP ou upgrade visual do App.
