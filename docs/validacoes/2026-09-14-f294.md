# Validação F294 — limites de segurança na sincronização de referências

## Alteração

`ReferenceSyncRunner` continua aceitando apenas URLs HTTPS dos domínios
permitidos e agora também valida a URL efetiva devolvida pelo `HttpClient`.
Isso impede que um redirecionamento silencioso leve a ingestão para outro host
ou esquema. Respostas que declaram `text/html` ou outro tipo não-JSON também
são rejeitadas antes da leitura e persistência.

Tipos ausentes continuam permitidos para compatibilidade com endpoints que não
enviam `Content-Type`; o JSON ainda é validado pelo parser antes de ser salvo.

## Testes

- `SyncRunnerRejectsRedirectToUnapprovedHost`: aprovado.
- `SyncRunnerRejectsExplicitlyNonJsonResponse`: aprovado.
- suíte `MyFrame.Core.Tests`: executada no PR; nenhuma escrita/rede real é
  necessária para os novos casos.

## Resultado

A sincronização de referências mantém o limite de domínio mesmo quando o
cliente segue redirects e não persiste respostas HTML acidentais. O acesso
real à Wiki/Overframe e sua autorização/licença continuam pendentes da F7;
esta fase não contorna bloqueios nem declara fontes externas homologadas.
