# Validação F199 — retry controlado de fontes Public Export

O cliente Public Export agora repete somente falhas transitórias (`408`, `429` e
erros `5xx`) até três tentativas. O atraso usa `Retry-After` quando fornecido,
com teto de dez segundos; na ausência do cabeçalho usa backoff curto. Respostas
`404`, payload inválido e cancelamento não são mascarados por retries.

## Evidências

```text
dotnet build MyFrame.Core.Tests/MyFrame.Core.Tests.csproj --no-restore -v:minimal
Build succeeded

dotnet vstest MyFrame.Core.Tests/bin/Debug/net10.0/MyFrame.Core.Tests.dll \
  --TestAdapterPath:MyFrame.Core.Tests/bin/Debug/net10.0 \
  --TestCaseFilter:"FullyQualifiedName~PublicExportTests"
Passed: 19, Failed: 0

dotnet vstest MyFrame.Core.Tests/bin/Debug/net10.0/MyFrame.Core.Tests.dll \
  --TestAdapterPath:MyFrame.Core.Tests/bin/Debug/net10.0
Passed: 175, Failed: 0

scripts/Test-McpFailureReadOnly.ps1 \
  -ServerPath artifacts/MyFrame-0.0.12-win-x64/MyFrame.Mcp.exe
MCP_FAILURE_READONLY_OK=1
MCP_FAILURE_NETWORK_CONNECTIONS=0
```

Os testes usam um handler local que devolve duas respostas `503` com
`Retry-After: 0` e depois `200`, além de verificar que `404` gera uma única
tentativa e o erro `PUBLIC_EXPORT_HTTP_404` original.

## Critérios

- [x] Falhas transitórias têm limite de tentativas.
- [x] `Retry-After` é respeitado e limitado.
- [x] Cancelamento interrompe espera e transporte.
- [x] Erros permanentes não sofrem retry.
- [x] Regressão Core aprovada.
- [ ] Homologação online com o endpoint oficial continua dependente de rede.
