# F218 — cobertura explícita na aquisição MCP

## Objetivo

Distinguir uma relação de aquisição ausente de uma relação que ainda não foi
observada pela fonte, evitando que uma lista vazia seja interpretada como fato.

## Implementação

`get_acquisition` agora retorna `coverage` com os campos:

- `catalog.components`;
- `catalog.relics`;
- `worldstate.bountyRewards`;
- `worldstate.motherTokens`.

Cada valor preserva `Known`, `NotObserved`, `NotSupported` ou `Invalid`, além do
estado/revisão das fontes. O contrato continua somente leitura.

## Validação

O smoke MCP semeado verifica `state=available`, as duas relações de catálogo,
bounty ativa e as chaves de cobertura. Resultado: 22 testes aprovados.
