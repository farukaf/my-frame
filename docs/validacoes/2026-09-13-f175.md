# Validação F175 — pacote distribuível Windows após hardening do MCP

## Objetivo

Confirmar que App, MCP e SyncHost continuam publicáveis juntos após a inclusão
da dependência DPAPI usada pelo armazenamento protegido de credenciais.

## Execução

```powershell
pwsh -NoProfile -File .\scripts\Build-Distribution.ps1 `
  -Version 0.0.6 -Configuration Release -RuntimeIdentifier win-x64
```

Resultado: `exit code 0`.

## Artefato

Diretório gerado: `artifacts/MyFrame-0.0.6-win-x64/`.

Executáveis presentes:

- `MyFrame.App.exe`
- `MyFrame.Mcp.exe`
- `MyFrame.Sync.exe`
- `e_sqlite3.dll`

Os PDBs dos três executáveis também foram produzidos. A publicação confirmou
que o MCP com `System.Security.Cryptography.ProtectedData` está incluído no
fluxo de distribuição e não quebrou a publicação dos demais componentes.

## Observações

O restore emitiu `NU1900` porque os feeds NuGet não estavam acessíveis para a
consulta de vulnerabilidades. Isso é um aviso de auditoria, não uma falha de
compilação; a validação de segurança dos pacotes deve ser repetida em CI com
acesso aos feeds.

- [x] SyncHost publicado para `win-x64`.
- [x] Processo terminou com código zero.
- [ ] Instalação limpa e execução em máquina Windows separada.
