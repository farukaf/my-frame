# Validação F185 — importação explícita de captura Overwolf pelo SyncHost

## Implementação

O executável `MyFrame.Sync` agora aceita:

```text
--overwolf-inventory-directory <dir> --allow-raw --data-root <root>
```

O modo usa o `CollectorCaptureInbox` existente, valida marker/hash/envelope e
publica a projeção no SQLite. O consentimento `--allow-raw` é obrigatório.

## Execução ponta a ponta

Um capture sintético foi produzido pelo `createCapture` real do pacote Node com
um equipamento Mesa Prime e um stackable Mother Token. A execução do SyncHost
retornou:

```text
state=published
source=overwolf-inventory
discovered=1
imported=1
rejected=0
EquipmentRecords=1
StackableRecords=1
UnknownRecords=0
```

O data root temporário criou `data.db`; ele foi removido ao final do teste.

## Consentimento

Executar o mesmo modo sem `--allow-raw` retornou:

```text
--overwolf-inventory-directory requires --allow-raw consent.
exit code 2
```

## Critério

- [x] Producer Node gera capture compatível.
- [x] SyncHost descobre e importa marker válido.
- [x] Projeção é publicada no SQLite.
- [x] Consentimento explícito é obrigatório.
- [x] Nenhum dado persistente do usuário foi usado.
