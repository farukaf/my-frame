# Validação F200 — retry compartilhado no World State

O transporte de fontes públicas foi centralizado em `SyncHttp`. O World State
oficial agora tem a mesma política do Public Export: até três tentativas para
`408`, `429`, `5xx` e timeouts, respeitando `Retry-After` e preservando o
fallback comunitário somente para falhas de transporte oficial.

## Evidências

```text
dotnet build MyFrame.Core.Tests/MyFrame.Core.Tests.csproj --no-restore -v:minimal
Build succeeded

dotnet vstest MyFrame.Core.Tests/bin/Debug/net10.0/MyFrame.Core.Tests.dll \
  --TestAdapterPath:MyFrame.Core.Tests/bin/Debug/net10.0 \
  --TestCaseFilter:"FullyQualifiedName~WorldStateTests|FullyQualifiedName~PublicExportTests"
Passed: 36, Failed: 0

dotnet vstest MyFrame.Core.Tests/bin/Debug/net10.0/MyFrame.Core.Tests.dll \
  --TestAdapterPath:MyFrame.Core.Tests/bin/Debug/net10.0
Passed: 177, Failed: 0
```

Os fixtures cobrem `503` seguido de sucesso, `Retry-After: 0`, timeout,
cancelamento implícito, `404`, payload inválido e fallback oficial → comunitário.

## Critérios

- [x] Política de retry compartilhada entre Public Export e World State.
- [x] Fallback comunitário não é usado para payload oficial inválido.
- [x] Fallback continua restrito a falha de transporte.
- [x] Regressão Core aprovada.
- [ ] Homologação online continua dependente de rede disponível.
