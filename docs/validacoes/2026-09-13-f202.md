# Validação F202 — cobertura rica do catálogo Public Export

A cobertura publicada no SQLite agora informa, sem inferência silenciosa, se a
revisão observou `components`, `relics`, `marketIdentity`, `imageName` e
`productCategory`, além dos campos básicos já existentes. A detecção é feita a
partir do JSON bruto validado da própria revisão; campos ausentes permanecem
`NotObserved`.

## Evidências

```text
dotnet build MyFrame.Core.Tests/MyFrame.Core.Tests.csproj --no-restore -v:minimal
Build succeeded

dotnet vstest MyFrame.Core.Tests/bin/Debug/net10.0/MyFrame.Core.Tests.dll \
  --TestAdapterPath:MyFrame.Core.Tests/bin/Debug/net10.0
Passed: 180, Failed: 0
```

O teste de cobertura publica um registro com componentes e identidade de mercado,
sem relíquias nem imagem, e verifica os estados `Known`/`NotObserved` no mesmo
SQLite consultado pelo leitor.

## Critérios

- [x] Componentes e relíquias têm cobertura explícita.
- [x] Identidade de mercado tem cobertura explícita.
- [x] Campos opcionais ausentes não viram valores inventados.
- [x] Cobertura permanece vinculada à revisão publicada.
- [x] Regressão Core aprovada.
