# Validação F201 — agregação dos documentos Public Export

O runner online deixou de selecionar apenas `ExportWeapons_en.json`. Ele resolve
todos os documentos `.json` do índice na mesma revisão, agrega registros por
`uniqueName`, rejeita conflitos de conteúdo e publica uma única geração SQLite.
Há limite explícito de 128 documentos e 256 MiB para evitar uma ingestão sem
limites; um índice vazio ou acima do limite falha sem substituir a revisão ativa.

Quando o índice contém um único documento, o caminho e o `revisionTag` continuam
aparecendo no resultado. Em uma revisão agregada, o resultado identifica
`aggregate:<quantidade>` e não inventa um único tag para documentos distintos.

## Evidências

```text
dotnet build MyFrame.Core.Tests/MyFrame.Core.Tests.csproj --no-restore -v:minimal
Build succeeded

dotnet vstest MyFrame.Core.Tests/bin/Debug/net10.0/MyFrame.Core.Tests.dll \
  --TestAdapterPath:MyFrame.Core.Tests/bin/Debug/net10.0
Passed: 179, Failed: 0
```

Fixtures locais agora cobrem dois documentos, deduplicação de registro idêntico
e rejeição de conflito. A confirmação com o índice online real permanece
pendente por indisponibilidade de rede nesta execução.

## Critérios

- [x] Mais de um documento pode compor uma revisão.
- [x] Conflito de `uniqueName` não é resolvido por precedência silenciosa.
- [x] Limites de quantidade e tamanho são explícitos.
- [x] Caso de documento único mantém compatibilidade do resultado.
- [x] Regressão Core aprovada.
- [ ] Publicação agregada com dados online reais.
