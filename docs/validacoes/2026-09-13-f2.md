# F2 — SQLite e publicação transacional

## Escopo

Esta fase entrega o primeiro armazenamento local para a plataforma de dados:

- schema versionado com fontes, execuções, staging, revisões e cobertura;
- publicação atômica em SQLite;
- backup consistente via SQLite Online Backup API;
- idempotência por `source_id + content_hash`;
- apenas uma revisão `active` por fonte, mantendo as anteriores como `retained`;
- leitura de status para a futura página de sincronização;
- lifecycle `SyncHost` com start/stop, tentativa e diagnóstico de falha;
- serialização do writer no processo e `busy_timeout` para concorrência entre processos.

O armazenamento ainda não é conectado ao MCP nem substitui o coletor F1. A captura GEP real continua sendo um gate independente.

## Limitações conhecidas

- backup/restore e compactação ficam para a fase de operação;
- o payload ainda é JSON bruto; normalização por entidade será feita após os fixtures reais;
