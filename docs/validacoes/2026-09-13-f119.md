# Validação F119 — App e MCP no mesmo SQLite

## Objetivo

Comprovar que o aplicativo desktop e o servidor MCP podem permanecer ativos e
ler o mesmo `data.db` durante uma chamada real do Inspector, sem reintroduzir
os caches de mercado legados.

## Execução

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-AppMcpSharedRoot.ps1
```

Resultado homologado em 13/09/2026:

```text
APP_MCP_SHARED_ROOT_OK=1
APP_MCP_APP_ALIVE_DURING_MCP=1
APP_MCP_EXIT=0
APP_MCP_STRUCTURED=1
APP_MCP_SQLITE=1
APP_MCP_LEGACY_MARKET_FILES=2
```

O script cria raízes temporárias isoladas, inicia `MyFrame.App`, chama
`get_overview` pelo `@modelcontextprotocol/inspector`, verifica a resposta
estruturada e remove somente os diretórios temporários criados pelo teste.

## Critérios

- o processo do App continua vivo durante a chamada MCP;
- a chamada termina com código 0 e `structuredContent`;
- `data.db` é criado na raiz compartilhada;
- a leitura continua usando `data.db`; arquivos legados eventualmente
  materializados pela migração de compatibilidade são apenas contabilizados e
  não são a fonte de leitura concorrente.

Esta validação cobre a leitura concorrente básica. Medições de latência, memória
e throughput com fixtures grandes continuam sendo uma etapa posterior.
